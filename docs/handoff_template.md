# Thread Handoff

Use a handoff only when responsibility moves to another top-level chat. It is a
delta, not a repository briefing. Include the concrete outcome, assigned
checkout and branch, task-specific boundaries, links to only the active owners
needed next, and non-obvious retained evidence.

Add current validation only when the next thread can rely on it. Add live state
only after fresh live preflight during handoff preparation, with timestamp and
timezone. Put durable work, issues, and contracts in their canonical repository
owners instead of copying them here. Omit generic startup guidance, safeguards,
status dumps, routine logs, commit lists, and stale volatile facts.

## Template

```text
Continue TheTower work in <assigned checkout> on <assigned branch>.

Outcome:
<one concrete result>

Boundaries:
- <task-specific constraint or authority limit>

Read:
- <exact active backlog, architecture, issue, or procedure link>

Evidence:
- <durable path and what it proves>
- <ephemeral path, labeled as such, only when material>
```

Omit empty headings, placeholder values, and `none` sections.
